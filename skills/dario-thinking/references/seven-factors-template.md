# 业务七要素拆解模板

把 Dario 的 "Big Blob of Compute" 七要素映射到企业业务流程。**目的：找到客户每个流程里最差的那一格——AI 化就从那里切。**

## 一、七要素对照表

| # | Dario AI 训练版 | 企业业务版 | 怎么观测 |
|---|---|---|---|
| 1 | 算力（Compute） | 人力/工时投入 | 这个流程占了多少人/多少小时 |
| 2 | 数据数量（Quantity） | 流程发生频次 | 每月/每周触发多少次 |
| 3 | 数据质量分布（Quality） | 输入信息标准化程度 | 输入数据是结构化还是散落各处 |
| 4 | 训练时长（Duration） | 单次流程耗时 | 完成一次需要多久 |
| 5 | 可扩展目标函数（Objective） | 是否有清晰成功标准 | "做对了"是什么样能不能验证 |
| 6 | 归一化（Normalization） | SOP 标准化程度 | 不同人做出来是否一致 |
| 7 | 数值稳定性（Stability） | 出错率/返工率 | 多少次需要返工或客户投诉 |

## 二、填写模板

对客户每个核心流程都填一张：

```
流程名称：___________________
（举例：销售提案撰写 / 订单审核 / 客户回访 / 质检报告生成）

┌──────────────────────────────────────────────────────────┐
│ 1. 人力投入：____ 人 × ____ 小时/月 = ____ 人月            │
│    [打分 1-5] ____ （5=人力极重，明显需要 AI 接管）         │
│                                                          │
│ 2. 频次：每月 ____ 次                                       │
│    [打分 1-5] ____ （5=高频，AI 化收益大）                  │
│                                                          │
│ 3. 输入标准化：__________ （描述输入信息的杂乱程度）        │
│    [打分 1-5] ____ （5=输入很乱，需要先做信息整合）         │
│                                                          │
│ 4. 单次耗时：____ 小时/次                                   │
│    [打分 1-5] ____ （5=耗时长，AI 加速效果明显）            │
│                                                          │
│ 5. 成功标准清晰度：__________                              │
│    [打分 1-5] ____ （5=标准模糊，AI 化难度高）             │
│    （注意：分数越高越难做，不是越好）                       │
│                                                          │
│ 6. SOP 标准化：__________                                  │
│    [打分 1-5] ____ （5=完全没 SOP，不同人做差异大）         │
│                                                          │
│ 7. 出错率：____ % 返工 / 投诉                               │
│    [打分 1-5] ____ （5=高错率，质量问题严重）              │
└──────────────────────────────────────────────────────────┘

最差格子：第 ___ 项
AI 化处方：从这一格切入
```

## 三、读分技巧（关键）

**重点不是总分，是哪一格最差。**

| 哪一格最差 | AI 化处方 |
|---|---|
| 1（人力重）+ 2（高频） | 自动化整个流程（最高 ROI） |
| 3（输入乱） | 先做信息整合 / 数据清洗 AI，不要急着做生成 |
| 4（耗时长） | 用 AI 做并行/批量处理，不一定全自动 |
| 5（标准模糊） | **不要做**，这是低可验证任务，会失败 |
| 6（无 SOP） | 先用 AI 帮客户建 SOP，再 AI 化 |
| 7（出错率高） | AI 做质检/校验，不是生成 |

## 四、填写示范

**示范 1：律所·合同初审流程**

```
流程名称：合同初审

1. 人力投入：3 律师 × 40 小时/月 = 120 小时/月  [打分 5]
2. 频次：每月 80 份合同  [打分 5]
3. 输入标准化：客户发来 PDF/Word/扫描件混合  [打分 4]
4. 单次耗时：1.5 小时/份  [打分 4]
5. 成功标准清晰度：有清单（合规要点 30 条）  [打分 2]
6. SOP 标准化：有 checklist  [打分 2]
7. 出错率：约 5% 漏审  [打分 3]

最差格子：第 1、2 项（人力+频次）
AI 化处方：自动化整个初审流程
- Claude 读取合同 → 按 30 条 checklist 输出风险点 → 律师只看 AI 标记的部分
- 预期：120 小时/月 → 30 小时/月（节省 75%）
- 置信度 ⭐⭐⭐（合同 AI 审查是成熟方案）
```

**示范 2：电商·客户回访流程**

```
流程名称：成交后客户回访

1. 人力投入：2 客服 × 60 小时/月 = 120 小时  [打分 5]
2. 频次：每月 500 单  [打分 5]
3. 输入标准化：订单信息齐全，但客户反馈散落  [打分 3]
4. 单次耗时：15 分钟/单  [打分 3]
5. 成功标准清晰度：模糊（"客户满意"）  [打分 4 ←警告]
6. SOP 标准化：有话术模板  [打分 2]
7. 出错率：低（只是没温度）  [打分 1]

最差格子：第 5 项（成功标准模糊）  ← 这是低可验证任务
AI 化处方：不要全自动化！
- 改成：AI 起草个性化回访话术 → 客服选用并发送
- 不要让 AI 直接发，因为"客户满意"无法被 AI 验证
- 置信度 ⭐⭐
```

## 五、避坑

❌ 不要把所有流程都打高分硬塞 AI
❌ 不要忽略第 5 格——成功标准模糊的流程不要做端到端 AI
❌ 不要一上来就推"AI Agent"，先看哪一格最差
❌ 不要给客户打所有低分流程的处方——先聚焦最差的 1-2 个流程
