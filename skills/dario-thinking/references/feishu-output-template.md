# 飞书文档输出模板与 lark-doc 调用

本 skill 最终交付物是飞书云文档。本文档说明：
1. 飞书文档的具体结构（标题层级、表格、引用）
2. 如何用 lark-doc skill 创建并写入

## 一、飞书文档完整结构

文档名：`《XX 公司 AI 化诊断与改造方案 v1.0》`

### 文档大纲（一级标题）

- 实施成本：__ 元（一次性）

### 4. 战略层：AI 化机会图谱

```
## 当前档位

你们目前在 **档 1（AI 辅助员工）**：
- 个别律师在用 ChatGPT 做翻译
- 没有公司层面的 AI 工具
- 没有数据沉淀

## 第一阶段目标：档 2（AI 嵌入工作流）

具体改变：
- 合同初审 AI 进入律师工作流
- 内部知识库 AI 问答
- 报告生成 AI 模板

不进入档 3 的原因：你们目前缺少数据治理能力，端到端 AI 还不到时机。

## 6 个月目标：档 3（AI 完成完整任务）

具体改变：
- 合同初审完全 AI 化（律师只 review 风险点）
- 客户咨询 AI 回答（律师只处理升级问题）

## 长期愿景：档 4 暂不规划

档 4 涉及替代律师角色，对你们的业务模式影响过大。本方案不在 6 个月内推这一档。
```

### 5. 战术层：核心改造点详解

```
## 改造点 1：合同初审 AI 化 ⭐⭐⭐

### 现状（一手证据）
> 你们在访谈中说："3 个律师每天就在审合同，没时间做更高价值的事。"

具体数据：
- 80 份/月 × 1.5h/份 = 120 小时/月
- 错误率 5%（约 4 份/月有漏审）

### 处方
工具栈：
- Claude（合同语义理解）
- 飞书多维表格（流程编排 + 结果存档）
- 飞书机器人（自动通知律师 review）

工作流：
1. 客户上传合同到飞书云空间
2. 自动触发 → Claude 按 30 条 checklist 检查
3. 风险点高亮，输出到飞书多维表格
4. 律师只 review AI 标红部分（5-10 分钟/份）

### 上行
- 120 小时/月 → 30 小时/月（节省 75%）
- 错误率 5% → <1%（AI 不会漏 checklist）
- 释放 2 个律师做高价值业务

### 下行
- 风险：AI 误判 → 律师 review 兜底
- 风险：合同格式异常 → fallback 到人工
- 不可逆风险：无（任何时候可切回纯人工）

### 落地节奏
- 第 1 周：跑通 10 份合同，验证准确率
- 第 2-3 周：调整 prompt 和 checklist
- 第 4 周：全量上线

### 验证标准
- 准确率 >95%
- 律师每份耗时 <10 分钟
- 客户/律师无投诉

---

## 改造点 3：__________
[同上结构]
```

### 7. 风险与边界

```
## 我们建议你们【不做】的事

1. **AI 主导客户谈判** — 涉及关系，是低可验证任务
2. **AI 自动签合同** — 法律风险不可逆
3. **裁掉所有律师助理** — 人在 AI 之上做监督，不要先裁人

## 这件事【做了不一定成】（标低置信度的）

1. AI Agent 端到端跑业务流（中国市场无成熟案例）
2. AI 对外客服（语气把控难度大）

## 客户【需要承担】的内部变革

AI 不能解决的事，你们要自己做：
1. 数据治理：合同模板、checklist、历史案例要数字化
2. 人员培训：律师要学会 review AI 输出
3. 客户沟通：告诉 VIP 客户"AI 在工作流内部使用，不直接对客"
```

## 二、用 lark-doc 创建文档

### 步骤 1：本地写好完整 Markdown 草稿

把上面所有部分填好，保存为本地 `.md` 文件。

### 步骤 2：让用户 review 草稿

不要直接发到飞书。先让瑶瑶看一遍，确认：
- 客户名称、行业、调研日期对
- 改造点优先级符合她对客户的判断
- 反共识发现部分她认可

### 步骤 3：调用 lark-doc 创建文档

参考 `lark-doc` skill 的命令。典型流程：

```
1. lark-cli docs create --title "XX 公司 AI 化诊断与改造方案 v1.0"
2. lark-cli docs update --token XXX --content @plan.md --format markdown
3. 返回飞书文档链接给用户
```

具体参数和命令请用 Skill 工具调用 lark-doc skill 获取。

### 步骤 4：询问后续动作

文档创建后问用户：
- 要不要分享给客户？
- 要不要导出为 PDF？
- 要不要做一份执行摘要 PPT（lark-slides）？
- 要不要做可视化卡片（doc-to-visual-card）？

## 三、Markdown → 飞书的格式注意

飞书 docx 对 Markdown 支持以下：
- ✅ 标题 # ## ###
- ✅ 表格
- ✅ 列表（有序/无序）
- ✅ 引用 >
- ✅ 代码块 ```
- ✅ 加粗 / 斜体

不支持的：
- ❌ 复杂嵌套表格 → 拆分成多张
- ❌ 数学公式 → 用图片
- ❌ 自定义颜色 → lark-doc 提供高亮 block

如果 Markdown 转 docx 后格式异常，参考 lark-doc 的 DocxXML 格式重新组织。
