# Amdahl 瓶颈识别问诊法

Dario 在访谈里说："你必须把所有阻止你闭环的东西从路上清掉。"
Amdahl 定律：**整体提升受限于最慢的那一环**。

应用到企业 AI 化：客户经常说"我们要全面 AI 化"——但全面 AI 化不存在，只有瓶颈 AI 化。

## 一、为什么瓶颈识别是核心

错误做法：
```
客户：我们要全面 AI 化
方案：客服 AI + 销售 AI + 财务 AI + 行政 AI + 数据 AI
结果：哪个都做不深，3 个月后客户失望
```

正确做法：
```
客户：我们要全面 AI 化
方案：先打 1 个瓶颈环节，做透，立标杆
结果：6 周后客户看见数据，自己来追加预算
```

## 二、瓶颈识别问诊法（4 问 1 写）

### 问 1：人力分布
> "你们公司哪个部门 / 哪个流程 占的人最多？"

人力多 ≈ 瓶颈所在。但不等于必须 AI 化——还要看可验证度。

### 问 2：延误事件
> "最近一次让你们头痛的延误 / 出错 / 客户投诉，是卡在哪一环？"

回忆最近的"事故"，这种事故反映的是真瓶颈，不是想象中的瓶颈。

### 问 3：老板时间
> "你（老板）自己的时间最多花在哪件事上？"

老板时间花在哪，瓶颈就在哪。这件事如果可以 AI 化，是最高 ROI 的改造点。

### 问 4：放大想象
> "如果这个环节的速度突然变 10 倍，整个公司效率会变多少倍？"

如果客户答"也变 10 倍"——这是真瓶颈
如果客户答"变 2-3 倍"——是次瓶颈
如果客户答"差不多"——不是瓶颈

### 写：瓶颈定位句

填这个模板（必须出现在方案的"现状诊断"部分）：

```
你们的 Amdahl 瓶颈是 __________。

理由：
1. 人力上：__________ 占了 __________ % 的人力
2. 出事上：最近 __________ 次延误都卡在这里
3. 老板时间上：__________ 花在这件事上的时间是 __________
4. 杠杆上：解决这个环节，整体效率能提升 __________ 倍

所以本方案的 P0 改造点是 __________。
其他环节即使能 AI 化，也放到第二阶段——先把瓶颈打掉。
```

## 三、常见伪瓶颈识别

客户经常会指错瓶颈，要警惕：

| 客户说的瓶颈 | 实际瓶颈 |
|---|---|
| "客服压力大" | 可能是产品问题导致投诉多，AI 客服只是缓解症状 |
| "销售线索不够" | 可能是产品定位不清，AI 找线索没用 |
| "员工执行力差" | 可能是 SOP 不清晰，AI 标准化 SOP 才是切入点 |
| "数据不准" | 可能是数据源散乱，AI 报表前要先治理数据 |
| "老板太累" | 可能是授权不清，AI 不能解决组织问题 |

**Dario 思维：症状 ≠ 瓶颈。**先诊断病因，再开药。

## 四、瓶颈类型分类（决定 AI 处方）

识别出瓶颈后，分类：

### A. 信息瓶颈（信息流不畅）
**症状：**信息散落、数据不通、汇总耗时
**AI 处方：**信息整合 / 检索 / 知识库
**典型工具：**Claude + 知识库 / 飞书多维表格 + AI / Dify

### B. 生产瓶颈（输出物产能不够）
**症状：**文档/报告/方案需求多但人手不够
**AI 处方：**内容生成 + 模板化
**典型工具：**Claude / GPT + workflow / 自定义 Skill

### C. 判断瓶颈（重复性判断耗人）
**症状：**审核 / 分类 / 打分占人力
**AI 处方：**规则化 + AI 分类
**典型工具：**Claude + structured output / Coze

### D. 沟通瓶颈（对外/对内沟通低效）
**症状：**重复回答相同问题、跨部门信息差
**AI 处方：**话术 AI / FAQ AI / 沟通中介
**典型工具：**Claude + workflow / 飞书机器人

### E. 协调瓶颈（流程编排耗时）
**症状：**多步骤流程、涉及多人配合、跟进难
**AI 处方：**流程编排 + 自动跟进
**典型工具：**n8n / 飞书工作流 / Make

### F. 决策瓶颈（高管决策时间稀缺）
**症状：**老板/中层每天被淹在小决策里
**AI 处方：**决策辅助 + 信息准备
**典型工具：**Claude + 知识库（不是 AI 决策！）

## 五、瓶颈识别后的处方决策树

```
识别出瓶颈
  ↓
这个瓶颈的可验证度是？
  ├─ 🟢 高可验证 → 全自动化处方
  ├─ 🟡 中可验证 → 半 AI 化处方
  └─ 🔴 低可验证 → 这不是真 AI 瓶颈，是组织瓶颈，告诉客户
  ↓
解决这个瓶颈的下行风险大吗？
  ├─ 小 → P0 第一阶段做
  ├─ 中 → P1 第二阶段做（先用次瓶颈练手）
  └─ 大 → 不要在第一阶段动这里
  ↓
客户有没有能力承接这个改造？
  ├─ 有（有人 / 有预算 / 有 SOP） → 直接做
  └─ 没有 → 第一阶段先建能力（培训/SOP/数据治理），不要急着上 AI
```

## 六、瓶颈识别完成的标志

你诊断出真正的瓶颈，应该满足：

1. ✅ 能用一句话讲清楚（不需要 5 个 bullet point）
2. ✅ 客户访谈里至少出现 3 次以上（一手证据）
3. ✅ 涉及客户最多人力 / 最多老板时间 / 最近事故
4. ✅ 解决它后，客户能自己感觉到差异（不需要外部数据证明）
5. ✅ 当前的可验证度允许 AI 化（不是 🔴）

如果做不到上面 5 点，**回到访谈稿继续读，瓶颈没找对**。
