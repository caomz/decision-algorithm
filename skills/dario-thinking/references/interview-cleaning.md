# 访谈稿清洗与标注规则

未清洗的 1-2h 访谈稿通常有以下问题：口水话、重复、跳跃、客户自我审查后的修饰。直接喂给分析会被噪音带偏。这份文档教你怎么读这种稿子。

## 一、读稿三遍法

**第一遍：不分析，只标注。**
通读全文，用心理标签标记每段：
- `[事实]` — 客户讲了一个具体事件、数字、流程
- `[情绪]` — 客户表达不满、骄傲、焦虑、无奈
- `[判断]` — 客户给出自己的看法、结论、归因
- `[废话]` — 寒暄、跑题、重复
- `[盲区]` — 客户讲到一半没讲清的关键信息

**第二遍：找真痛点。**
真痛点的三个特征：
1. 客户**反复**提（同一件事在访谈中出现 3 次以上）
2. 客户讲这件事时有**情绪**（叹气、抱怨、声音变大、用极端词）
3. 客户能**给出具体例子**（"上周就有一单..."而不是"我们经常遇到..."）

**伪痛点的特征：**
- 客户用"也"字带过（"流程效率也是个问题"）
- 客户引用别人的话（"我们 CTO 觉得..."）
- 客户讲完没有具体例子
- 客户主动说但接下来转移话题

**第三遍：找盲区。**
访谈中暴露但客户自己没意识到的问题：
- 客户描述流程时漏掉的环节（"然后就交付了"——交付质检谁做？）
- 客户提到一笔带过的工具/系统（可能是真瓶颈）
- 客户讲两个流程时矛盾的地方
- 客户说"这个不是问题"但你听出来是问题的地方

## 二、信息提取清单

读完后填这张表（自己心里有数，不一定输出给用户）：

```
公司基本面
├─ 行业 / 规模 / 团队人数
├─ 主要业务模式（B2B/B2C/混合）
├─ 决策结构（老板说了算 / 委员会 / 部门长）
└─ AI 成熟度（从未用 / 个人在用 / 公司层面用）

业务流程
├─ 核心流程 1：__________
│   ├─ 频次：每月多少次
│   ├─ 单次耗时：多少小时/人
│   ├─ 投入人力：多少人 × 什么角色
│   ├─ 输出物：什么文档/数据/产出
│   ├─ 出错率：多少返工
│   └─ 当前用什么工具
├─ 核心流程 2、3...

真痛点（每条都要有具体例子）
1. __________  例子：__________
2. __________  例子：__________
3. __________  例子：__________

伪痛点（识别出来不分析）
1. __________  原因：__________

盲区（客户没意识到的）
1. __________
2. __________

资源约束
├─ 预算量级（万 / 十万 / 百万）
├─ 时间窗口（多久要见效）
├─ 谁在推（老板 / 部门长 / 中层）
└─ 内部反对声音
```

## 三、客户的常见自我审查

访谈中客户经常会做"政治正确"的自我审查，要识破：

| 客户说的话 | 真实意思 |
|---|---|
| "我们流程很标准化" | 通常意味着 SOP 没人执行 |
| "员工都很愿意学 AI" | 通常意味着没人在用 |
| "我们已经在用 ChatGPT 了" | 通常是个别员工自费在用 |
| "数据我们都有" | 通常数据散在 N 个系统里 |
| "我们老板很支持" | 通常老板没投钱 |
| "我们要做 AI 转型" | 通常要做的是个别工具替换 |

听到这些话不要照单全收，要追问具体例子。如果客户给不出具体例子，**就当 ta 没说过**。

## 四、提问追加清单（如果稿子信息不够）

如果访谈稿里关键信息缺失，列出来一次性问用户。常见缺失：

1. **流程频次和耗时**：每月多少次？每次几小时？
2. **人力分布**：谁做这件事？多少人？什么职级？
3. **当前工具**：用什么系统？数据存在哪？
4. **历史尝试**：之前试过什么 AI 工具？为什么没用起来？
5. **决策链**：谁拍板？预算谁批？
6. **时间窗口**：多久要见到效果？
7. **内部阻力**：哪些人/部门可能反对？
