# 非对称风险矩阵

Dario 算了一笔账：如果他以为 2027 年收入 1 万亿、订了 1 万亿算力，结果实际是 8000 亿——**地球上没有任何对冲能阻止他破产**。

这是 Nassim Taleb 的非对称性思维：**决策不看期望值，看最坏情况下你是否还活着。**

应用到企业 AI 化：**第一阶段不能放任何"上行小+下行大"或"下行不可逆"的改造点。**

## 一、四象限矩阵

```
                上行收益
                  ↑
                  │
    ┌─────────────┼─────────────┐
    │             │             │
    │  上行小     │  上行大      │
    │  下行大     │  下行大      │
    │  ✘ 不做     │  △ 第二阶段   │
    │             │             │
────┼─────────────┼─────────────┼──→ 下行风险
    │             │             │
    │  上行小     │  上行大      │
    │  下行小     │  下行小      │
    │  ⚪ 练手用   │  ✓ P0 必做   │
    │             │             │
    └─────────────┼─────────────┘
                  │
                  ↓
```

## 二、四象限处方

### ✓ 上行大 + 下行小 → P0 必做
- **特征：**做成了大幅提效，做坏了损失也小
- **典型：**内部用 AI 起草文档、Claude Code 提效、知识库 AI 问答
- **第一阶段就放，建立信心**

### △ 上行大 + 下行大 → 第二阶段
- **特征：**潜力大但失败代价高
- **典型：**端到端 AI 客服（做坏了客户跑光）、AI 主导销售（做坏了订单丢）
- **不要在第一阶段做**，先用 ✓ 项目建立信心和数据

### ⚪ 上行小 + 下行小 → 练手用
- **特征：**收益不大但安全
- **典型：**给员工配 AI 助手、内部 FAQ 机器人
- **可以放第一阶段练手**，让团队建立 AI 使用习惯

### ✘ 上行小 + 下行大 → 永远不做
- **特征：**没多大用还可能搞砸
- **典型：**为了赶 AI 风潮做 PR、强推 AI 把员工搞跑
- **明确告诉客户不要做**

## 三、下行风险评估清单

每个改造点都问 5 个问题，识别下行：

### 1. 客户层面
- [ ] AI 出错会被客户直接看到吗？
- [ ] 出错会影响客户的业务/品牌/信任吗？
- [ ] 出错能在 24 小时内修复吗？

### 2. 业务层面
- [ ] AI 出错会导致订单/合同/收入损失吗？
- [ ] 损失能挽回吗（金额上）？
- [ ] 损失能挽回吗（声誉上）？

### 3. 法律/合规层面
- [ ] 涉及个人隐私数据吗？
- [ ] 涉及金融、医疗、法律等强监管行业吗？
- [ ] 出错会导致诉讼/罚款吗？

### 4. 组织层面
- [ ] 改造涉及裁员/转岗吗？
- [ ] 改造需要跨部门协作吗？
- [ ] 主要决策人内部有反对吗？

### 5. 技术层面
- [ ] 失败时能立即切回人工吗？
- [ ] 关键数据有备份吗？
- [ ] 依赖第三方服务吗（中断风险）？

**任何一项答"是"，下行风险就要升级一档。**
3 项以上答"是"，必须放到第二阶段或不做。

## 四、写到方案里的格式

每个改造点都要写"上行/下行"两栏：

```
改造点 X：合同初审 AI 化

上行（最好情况）
- 节省 75% 律师工时
- 单月节约 90 小时
- 律师可以处理更多案子
预期：节约成本 X 万/月

下行（最坏情况）
- 风险 1：AI 漏审某条款 → 律师 review 兜底，影响可控
- 风险 2：客户对 AI 审查不放心 → 不告知客户，AI 在律师工作流内部使用
- 风险 3：合同格式异常导致 AI 卡住 → 自动 fallback 到人工
- 不可逆风险：无（任何时候可以切回纯人工）
止损：第 1 周如果效果差，立即停止

判断：上行大 + 下行小 → P0 必做
```

```
改造点 Y：AI 端到端跑客户回访

上行（最好情况）
- 完全释放 2 个客服人力
- 24 小时无间断回访
- 客户感受个性化

下行（最坏情况）
- 风险 1：AI 说错话 → 客户投诉、品牌受损（不可挽回）
- 风险 2：AI 信息泄露 → 法律风险
- 风险 3：客户不接受 AI → 流失客户
- 不可逆风险：声誉损失难恢复
止损：很难止损，因为客户已经看到了

判断：上行大 + 下行大 → 第二阶段，先在 5% 流量上试
```

## 五、客户经常误判下行风险

⚠️ **客户经常以为下行小，其实下行大：**

| 客户以为 | 实际下行 |
|---|---|
| "AI 写一封邮件给客户" | 邮件出错可能影响合作 |
| "AI 帮我们发朋友圈" | 公众内容出错品牌受损 |
| "AI 处理简单投诉" | 投诉被激化反而升级 |
| "AI 自动审批小额单" | 规则漏洞被员工/客户钻 |

⚠️ **客户经常以为下行大，其实下行小：**

| 客户以为 | 实际下行 |
|---|---|
| "AI 起草文档让员工不会写了" | 员工只是少写初稿，能力不会丢 |
| "用 AI 数据被泄露" | 私有部署或不传敏感数据就行 |
| "AI 替代人会被员工抵制" | 让员工成为 AI 的"管理者"，反而欢迎 |

**指出客户的下行误判 = 你的差异化输出。**

## 六、Dario 式资源分配公式

每个改造点的资源投入按这个比例：

```
分配比例 = 上行收益 × 置信度 ÷ 下行风险

举例：
合同初审 AI：上行 8 × 置信度 1.0 ÷ 下行 1 = 8
端到端 Agent：上行 9 × 置信度 0.3 ÷ 下行 8 = 0.34
```

**资源向 8 倾斜，不向 0.34 押注。**这就是 Dario 在 Anthropic 决定算力采购的逻辑。

## 七、第一阶段红线

第一阶段（前 4 周）的改造点必须满足：

✅ 落在右下象限（上行大+下行小）
✅ 任何下行风险都可逆（能立即切回人工）
✅ 不涉及组织变革（不裁员、不重组）
✅ 不直面客户（AI 在内部工作流，不直接对外）
✅ 失败后客户的整体业务不会受影响

**这是 Dario 思维的底线：先活下来，再求增长。**
