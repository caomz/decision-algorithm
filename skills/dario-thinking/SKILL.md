# Dario 思维 × 企业 AI 化诊断

## 一、本 Skill 的定位

这不是通用 AI 诊断 skill，是**用 Dario 思维操作系统跑一遍企业访谈稿**，得到一份不会画饼、可落地、敢标置信度的全栈方案。

---

## 二、输入处理：1-2h 未清洗稿的标准动作

收到访谈稿后**不要直接开始分析**，先做三件事：

### 1. 清洗扫描（不重写，只标注）
扫描全文，在心里建立标注（不要输出给用户）：
- **核心事实**：客户当前流程、人员、工具、关键数字
- **真痛点**：客户反复提、有情绪、能给出具体例子的（≠ 客户嘴上说的"痛点"）
- **伪痛点**：客户说"这个也是问题"但讲不出具体场景的，标记忽略
- **一手证据 vs 二手叙事**：客户亲历的事 vs 客户听说的行业趋势——只用一手证据
- **没说出来的瓶颈**：访谈中暴露但客户没意识到的问题（这是你的差异化输出）

### 2. 信息完整度自检
访谈通常会缺关键信息。在分析前一次性列出缺失项问用户：
- 团队规模 / 角色分工
- 当前已用的工具/系统
- 关键流程的耗时和频次（"每月做几次""每次几小时"）
- 预算量级 / 决策人 / 时间窗口

**规则：** 如果只缺 1-2 项非关键信息，基于行业常识补全并标注 `[假设: ...]`，不阻塞主流程。如果关键信息（业务流程都没讲清楚）缺失，必须问。

### 3. 客户分级判断
读完访谈稿，先在心里给客户打分（影响方案颗粒度）：
- **AI 成熟度**：从未用过 / 用过 ChatGPT / 已有 AI 工具栈
- **变革决心**：观望试水 / 明确要做 / 已经在做但效果不好
- **执行力**：有人做 / 需要外部代做 / 老板亲自抓

成熟度+决心+执行力 决定方案要写多深、推什么档位。

## 三、Dario 思维 6 工具：每一步对应一个动作

按这个顺序跑，不要跳步。每一步对应 Dario 的一个思维工具。

### 工具 1：七要素拆解（Big Blob of Compute → 业务版）

把客户的核心业务流程拆成 7 个可观测变量。**不是发明新维度，是把 Dario 的 7 要素映射到业务上：**

| Dario 七要素（AI 训练） | 业务版七要素（企业流程） |
|---|---|
| 算力 | 人力/工时投入 |
| 数据数量 | 流程发生频次 |
| 数据质量分布 | 输入信息的标准化程度 |
| 训练时长 | 单次流程耗时 |
| 可扩展目标函数 | 是否有清晰的成功标准 |
| 归一化 | 流程标准化/SOP 程度 |
| 数值稳定性 | 出错率/返工率 |

对客户每个核心流程都填这 7 格。**哪一格最差，AI 化就从哪一格切**——而不是套模板说"用 AI 做客服"。

### 工具 2：可验证度分级（核心动作）

把客户访谈里出现的所有任务/流程做这个分级：

| 等级 | 定义 | AI 化处方 |
|---|---|---|
| 高可验证 | 输出有客观对错（数据录入、合规检查、订单匹配、报表生成） | **立刻全自动化**，模型 + workflow |
| 中可验证 | 输出有主观但可检查（销售话术、客服回复、文案初稿） | **半 AI 化**，模型生成 + 人工兜底 |
| 低可验证 | 输出无客观标准（战略判断、人事决策、创意方向） | **暂不动**，最多做信息整合辅助 |

**这是方案优先级的根本依据。** 不要把低可验证任务排到 P0——客户会失望，你会失信。

### 工具 3：Amdahl 瓶颈识别

客户经常会要"全面 AI 化"。Dario 的反应是：找最慢的那一环。

**问自己 3 个问题：**
1. 如果只能改一个环节，改哪个对客户整体效率提升最大？
2. 客户已经投入最多人力的环节是哪个？（人力多≈瓶颈所在）
3. 客户最近一次"延误/出事"是卡在哪一环？

回答这三题之后，**P0 只能是瓶颈环节，不能是"看起来酷的环节"**。

### 工具 4：二元命题拆谱系（写方案时强制使用）

客户问"我们能不能 AI 化？"，**永远不要回答"能/不能"**。强制拆成 5-7 档：

```
档 1：AI 辅助员工（个人提效，员工自己用 ChatGPT/Claude）  ← 大部分公司在这
档 2：AI 嵌入工作流（具体场景接入，比如客服自动回复）
档 3：AI 完成完整任务（端到端，比如自动生成报告）
档 4：AI 替代某个角色（不再需要某岗位的初级工作）
档 5：AI 主导业务流（人只做异常处理）
档 6：AI 重构商业模式（产品/服务形态本身因 AI 改变）
```

每份方案必须告诉客户：**你现在在档几，建议第一阶段冲到档几，长期目标到档几。**

### 工具 5：分层置信度（方案里每个判断都要标）

每个推荐都要带一个置信度等级。**不是装严谨，是为了让客户知道哪里可以赌、哪里要试。**

| 标记 | 含义 | 适用场景 |
|---|---|---|
| ⭐⭐⭐ 高置信 | 这件事别人做过、效果验证过 | 客服话术 AI、合同条款审查、报表自动化 |
| ⭐⭐ 中置信 | 技术成熟但客户场景适配性需验证 | 销售线索打分、内部知识库 AI 化 |
| ⭐ 低置信/探索 | 创新但有失败风险 | AI Agent 端到端跑业务、AI 主导决策 |

**禁止给所有方案都打 ⭐⭐⭐**——这是画饼的标志。一个全栈方案里 ⭐ 和 ⭐⭐⭐ 应该都有。

### 工具 6：非对称风险矩阵（执行路线图必用）

排路线图时**永远先问下行**：

```
┌────────────────────────────────────────┐
│  上行小+下行大：不做（即使省时间也别推） │
│  上行大+下行大：做但只在第二阶段        │
│  上行小+下行小：第一阶段练手用         │
│  上行大+下行小：P0，无脑做             │
└────────────────────────────────────────┘
```

第一阶段（前 4 周）只放"上行明确 + 下行可控"的改造点。**不要在第一阶段推任何会改组织架构、改客户接口的东西**——失败了客户对 AI 化的信心就废了。

## 四、输出：飞书云文档全栈方案

### 文档结构（必须按这个顺序）

输出到飞书前，先在本地组织好下面 6 部分内容：

```
《XX 公司 AI 化诊断与改造方案》

封面页：
  - 客户名称 / 行业 / 调研时间 / 方案版本

第一部分 · 执行摘要（1页）
  - 三句话讲清楚：你们现在在档几 / 第一阶段冲到档几 / 终态是什么
  - 三个 P0 改造点（标置信度）
  - 预期产出：6 周内 / 3 个月 / 6 个月

第二部分 · 现状诊断
  - 业务七要素扫描表（七要素 × 客户核心流程）
  - 可验证度分级表（任务 × 等级 × 处方）
  - Amdahl 瓶颈定位（一句话讲清楚客户最大的卡点）
  - 反共识发现（客户没意识到的机会，1-3 条，⭐ 你的差异化输出）

第三部分 · 战略层：AI 化机会图谱
  - 当前所在档位 → 第一阶段目标档位 → 终态
  - 为什么是这个档位（用 Dario 思维论证）
  - 关键判断标置信度

第四部分 · 战术层：3-5 个核心改造点
  每个改造点：
    - 现状（一手证据，引用访谈原话）
    - 处方（具体工具 + 工作流，不说"用 AI"这种废话）
    - 置信度 ⭐⭐⭐ / ⭐⭐ / ⭐
    - 上行（量化收益：节省 X% 时间 / 释放 Y 人力）
    - 下行（最坏情况是什么，怎么兜底）
    - 验证方式（怎么知道做成了）

第五部分 · 执行层：分阶段路线图
  阶段 1（0-4 周）：上行大+下行小的改造点 ← 建立信心
    - 第 1 周做什么 / 谁做 / 验证标准
    - 第 2-4 周做什么 / 谁做 / 验证标准
  阶段 2（1-3 月）：核心瓶颈攻坚
    - 改造点列表 + 时间窗
    - 需要客户配合的资源
  阶段 3（3-6 月）：进入下一档位
    - 这个阶段的目标档位
    - 关键风险

第六部分 · 风险与边界
  - 我们建议不做什么（低可验证任务 / 高下行风险动作）
  - 做了不一定成的事（标低置信度的）
  - 客户需要承担的内部变革（不是 AI 能解决的）
```

### 写作硬规则

✅ **必须做：**
- 每个判断引用访谈原话（一手证据）："你们提到 XX 时说 ......"
- 每个工具推荐写到具体产品名（Claude / Dify / 飞书多维表格 + AI / n8n / Coze）
- 每个收益给数字范围（"节省 60-70% 文案产出时间"）
- 每个改造点标置信度
- 每个阶段写清楚验证标准

❌ **禁止：**
- "赋能""助力""数智化""降本增效"等空词
- "可以用 AI ......"这种没指明工具的废话
- 给所有方案都打 ⭐⭐⭐
- 在第一阶段放高下行风险的改造点
- 引用客户没说过的"行业共识"画饼

### 输出到飞书的衔接

本地内容组织好后，使用 **lark-doc** skill 创建飞书云文档：

1. 先在本地写完整 Markdown 草稿，让用户确认结构
2. 用户确认后，调用 lark-doc 的 docs 命令创建飞书文档
3. 文档创建后返回链接给用户
4. 询问是否需要分享给客户/团队

参考 `references/feishu-output-template.md` 获取飞书文档的具体格式要求。

## 五、主动补位：5 件用户没要求但你必须做的事

按 CLAUDE.md 的"主动补位"原则，每次出方案都要附加：

1. **指出访谈本身的盲区**：客户没讲清楚的关键信息，建议下次访谈追问什么
2. **找出可独立做内容的观点**：访谈中如果有可以单独做小红书/抖音内容的洞察，列在文档末尾"内容素材"附录
3. **指出客户的反共识机会**：客户自己没意识到的 AI 化机会（这是你的差异化）
4. **标记需要长期跟踪的指标**：方案落地后客户要监控什么数据
5. **预判客户会怎么反对方案**：列出 2-3 个客户最可能的质疑 + 你的回应

这 5 件事放在方案文档的最后一节"附录"里，**让客户感觉到你想得比他多**。

## 六、反模式（绝对不要做的事）

❌ 没读完访谈稿就开始分析（必须读完再下笔）
❌ 把客户嘴上的"痛点"直接当真痛点（要看具体例子和情绪）
❌ 套通用模板（每家公司的瓶颈不一样，不要复制粘贴）
❌ 推荐自己没用过 / 不确定的工具（推 Claude Code 因为你了解，不要瞎推 LangChain）
❌ 第一阶段就推组织变革（先建信心再动结构）
❌ 给客户画万亿饼（"全面 AI 化后效率提升 10 倍"——Dario 自己都不会这么说）
❌ 不区分一手证据和行业叙事（只用客户访谈里能直接观测到的事实）

## 八、调用流程总览

```
1. 用户提供访谈文字稿
   ↓
2. 清洗扫描 + 信息完整度自检 + 客户分级
   ↓
3. 缺关键信息 → 一次性问用户补充
   ↓
4. 跑 Dario 6 工具：
   七要素 → 可验证度 → Amdahl → 拆谱系 → 置信度 → 非对称风险
   ↓
5. 本地组织 6 部分文档结构
   ↓
6. 给用户看 Markdown 草稿确认
   ↓
7. 用户确认后 → 调用 lark-doc 创建飞书文档
   ↓
8. 返回飞书链接 + 主动补位 5 件事
```

记住：**这份方案是给客户看的，但骨架是 Dario 思维。**客户不需要知道 Dario 是谁，但 ta 会感觉到这份方案"敢说话、有立场、不画饼"——这就是 Dario 思维的价值。
