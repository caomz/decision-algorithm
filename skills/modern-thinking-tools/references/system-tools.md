# 关系与系统工具

关系问题必须承认他人的能动性；组织问题必须同时看人、角色、激励和反馈。不要把结构问题简化成“谁是坏人”。

## 一、关系、合作与社会互动

| 工具 | 解决什么问题 | 操作问题 |
| --- | --- | --- |
| 他人的能动性 | 别把他人当可控制的 NPC | 对方有哪些目标、约束、选择权和退出权？ |
| 地位 | 识别尊重、钦佩和自愿让步的分配 | 当前冲突是在争结果，还是争谁有资格定义结果？ |
| 能力 × 温暖 | 区分“能做事”与“意图可信” | 对方怀疑的是我的能力还是意图？ |
| 礼/互动协议 | 降低摩擦、同步预期、修复错误 | 身份、语义、边界和道歉/修复协议是否清楚？ |
| 安全基地/港湾 | 区分支持探索与承接受伤 | 此刻对方需要被保护、被听见，还是被鼓励行动？ |
| 第三物 | 把人对人的僵局改成人围绕对象协作 | 能否拿出草案、数据、时间线、原型或共同清单？ |
| 道德可扩展性 | 不把家庭、市场、组织、国家的规则混用 | 当前关系尺度是什么？应认人、认证据，还是认程序？ |
| 自我约束 | 用可靠边界建立信任 | 哪个承诺能被验证？违约后如何修复？ |

## 二、制度与激励

| 工具 | 解决什么问题 | 操作问题 |
| --- | --- | --- |
| 激励相容 | 让普通人追求自身利益时也完成系统目标 | 奖励、成本、信息和权力是否把行为推向正确方向？ |
| 柠檬市场 | 好坏不可验证导致好货退出 | 如何让质量、过程和责任可见、可验、可申诉？ |
| 外部性 | 行动成本被转嫁给局外人 | 谁获益、谁付钱、谁承担长期副作用？ |
| 软预算约束 | 预期有人兜底导致责任变形 | 支持是否有条件、上限、复盘和退出机制？ |
| 可读性与米提斯 | 统一管理抹掉现场知识 | 哪些数据必须标准化，哪些判断必须留给现场？ |
| 共同知识 | 人人知道还不够，还要知道彼此都知道 | 怎样把私下认知变成公开、可见的共同承诺？ |
| 非预期后果 | 好意图经激励与预期反应后变坏结果 | 新规则会怎样改变人的行为，而不是只改变口号？ |
| 慢变量 | 保护不显眼但决定韧性的基础 | 信任、规则、能力、基础设施中哪项不能为短期数字牺牲？ |

## 三、组织与管理

| 工具 | 解决什么问题 | 操作问题 |
| --- | --- | --- |
| 替罪羊/系统思维 | 防止把多重防线失效归咎于一个人 | 哪几道防线同时失效？个人困扰背后是否有公共结构？ |
| 摩洛克/多极陷阱 | 每个人理性却把集体推向坏结局 | 哪个单一赛道迫使所有人加码？能否引入价值多元或协调规则？ |
| 组织资本 | 沉淀谁擅长什么、怎样配合最顺 | 认知、结构和关系知识怎样流动并留下？ |
| 叙事权 | 把判断变成集体行动 | 要定的题、定义和共同身份分别是什么？ |
| 角色责任 | 从对某个人负责转向对角色和制度负责 | 权利、责任、接口和替代机制是否脱离私人关系？ |
| 古德哈特定律 | 指标一变目标就扭曲现实 | 哪个指标正在被优化？谁保留最终判断权？ |
| 指挥官意图 | 放权时仍保持方向和边界 | 为什么做、成功长什么样、哪些东西不能牺牲？ |
| 委托—代理 | 处理利益分歧与信息不对称 | 目标解释权、信息解释权和最终裁判权由谁保留？ |
| 流程/清单/经验库 | 把个人聪明外置成系统 | 哪些步骤是技能、哪些是护栏、哪些经验应进入记忆？ |
| 基线漂移 | 异常反复无事后逐渐变成默认 | 原基线是什么？越界如何留下判例并触发修复？ |
| 认领—授予—授权 | 用承担小不确定性赢得更大杠杆 | 哪个问题可以先认领并闭环，让组织愿意授予资源？ |
| 可托付性 | 以确定性交付换信任和高杠杆 | 我输出的是忙碌，还是可预期的结果与反馈？ |

## 四、复杂系统、创新与长期变化

| 工具 | 解决什么问题 | 操作问题 |
| --- | --- | --- |
| 生成 | 创造不依赖创始人也能继续演化的东西 | 它能否组织闭合、离开我运行并允许后人改进？ |
| 对称性破缺 | 识别尚可改变与已经固化的状态 | 系统还“热”吗？哪个序参量会让一个方向被固化？ |
| 临近可能 | 不跳跃幻想，只做当前够得着的一步创新 | 哪个一步可达的组件会打开下一扇门？ |
| 反馈回路 | 控制会自我强化或自我稳定的系统 | 哪条正反馈要启动，哪条负反馈要建立？ |
| 自组织临界 | 在僵死和失控之间维持活力 | 能否慢加载、快释放、留出口并用局部规则治理？ |
| 边际分析 | 判断继续投入是否仍划算 | 下一单位投入的收益与成本是多少？S 曲线到哪了？ |
| 第二曲线 | 在旧增长见顶前启动新增长 | 新曲线是否已有小规模真实证据？ |
| 路径创造 | 不空谈摆脱路径依赖，借旧资源养新路 | 如何造路、导流并在成熟后退役旧路径？ |
| 最小可行生态 | 新路径不能只有单点项目 | 是否有人员、权限、预算、流程、指标和反馈闭环？ |
| 适应性循环 | 看懂开拓、守成、释放、重组 | 当前处于 r、K、Ω 还是 α？此阶段应保护什么、释放什么？ |
| 零阶道理 | 在复杂信息里保住方向、量级和机制 | 哪一两条因果回路足以决定结论？ |
| 立题 | 选择规则和问题，而不只在给定题里答题 | 题干藏了什么预设？谁拥有问题、边界和成败标准的定义权？ |
| 稀缺位置 | AI 普及后价值从通用能力移向位置 | 空白处、担保人、关系人中，我能占哪个位置？ |
| 预训练/后训练 | 区分能力上限与可靠下限 | 我需要扩大经验语料，还是在真实反馈中练到稳定交付？ |

## 关系问题的输出补丁

- 不给未在场的人做人格诊断。
- 区分一次事件、重复模式和结构性伤害。
- 尊重用户边界，也承认对方有拒绝、协商和退出权。
- 若存在暴力、胁迫、跟踪、财务控制或现实安全风险，优先安全计划和专业支持，不以“沟通技巧”替代。

## 组织问题的输出补丁

- 同时写出目标、角色、激励、信息、反馈和退出机制。
- 先止血再改系统；止血成功不等于根因解决。
- 不把“加强考核”当默认答案。指标必须配合抽查、申诉、人工判断和反作弊设计。
- 建议必须说明 owner、验收证据和复盘周期；没有这些，就只是口号。
